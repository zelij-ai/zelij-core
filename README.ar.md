**أنشئ شركتك الناشئة المبنية بالكامل على الذكاء الاصطناعي.** مكتب واحد يعمل فيه أربعة وكلاء من أجلك: هم يقترحون، وأنت تقرر. جهازك، مفتاح Claude الخاص بك، بياناتك؛ لا شيء يرسل أي معلومة إلى أي جهة.

![حوض Zelij Core: المؤسس وأربعة وكلاء يتبادلون الحديث ويقترحون القرارات وينفذون ما تمت الموافقة عليه](docs/img/aquarium.gif)

*الحوض خلال يوم محاكى (معروض هنا بالفرنسية). في تثبيتك الخاص، كل بطاقة هي فعل حقيقي لوكلائك، مباشرةً وقابل لإعادة التشغيل على مدى أربع وعشرين ساعة. اللون الذهبي هو أنت: لا يحدث أي شيء ملزم قبل قرارك. الوجوه لشخصيات خيالية.*

## ما الذي تفعله النواة

- **المكتب**: صفحة واحدة. القرارات المعلقة، طلب إلى رئيس الديوان، آخر عمليات التنفيذ مع تكلفتها، السجل، الوكلاء، الوحدات المثبتة.
- **حزمة القرار**: الهدف، الاقتراح، لماذا الآن، الخيارات، التوصية، المخاطر، قابلية التراجع، الخطة، الرجوع، الأثر. الحزمة غير المكتملة لا تُفتح. وافق أو ارفض أو اطلب تغييرات مع تعليمة إلزامية تُنقل إلى الوكيل.
- **قواعد البيت**: لا شيء ملزم (مال، ظهور علني، حذف، أمر لا رجعة فيه) يتم دون قرار؛ كل واقعة مؤرخة وموثقة المصدر أو موسومة بـ «غير متحقق منه»؛ السجل لا يُمحى أبدًا.
- **البوابة**: مفتاح Claude الخاص بالمؤسس، تكلفة كل نداء محسوبة من الاستهلاك والأسعار العلنية المؤرخة، سقف شهري يحجب عند بلوغه.
- **المنفذ**: حلقة نداءات محدودة (ميزانية أدوار لكل وكيل)، أدوات مقتصدة، رفض النموذج يُعامل كنتيجة.
- **الوحدات**: الطريقة الوحيدة لتوسيع النواة. واجهة مستقرة، بيان `pack.json` موقّع بـ Ed25519 من الناشر، بصمة كل ملف مشمولة بالتوقيع، تحقق قبل التثبيت. أهداف النشر والوكلاء الإضافيون يمرون كلهم من هنا.
- **المالية**: مبيعات مؤكدة (استيراد Stripe للقراءة فقط أو إدخال يدوي مع إثبات)، مصاريف مصرح بها تتكرر كل شهر، تكلفة الوكلاء مقيسة، سجل الشهر، تصدير CSV للمحاسب. لا شيء يُصرح به أو يُفوتر.
- **جهات الاتصال**: بطاقة لكل شخص، أساس قانوني إلزامي، مدة الاحتفاظ، المراسلات، الحقوق الممارسة؛ جهة الاتصال المعترضة لا تتلقى شيئًا بعد ذلك، وجهة الاتصال المنتهية تُنسى ولا يبقى سوى سجل الحقوق.
- **النشر**: الصفحة التي يكتبها وكيل التسويق تصبح مسودة ثم قرارًا؛ وبعد الموافقة تُقترح على الموقع كطلب دمج في GitHub أو مسودة WordPress. الخطوة الأخيرة، الدمج أو النشر، لك أنت.
- **في جيبك**: كل قرار يصل إلى هاتفك، بالبريد الإلكتروني مع رابطين موقّعين لاستخدام واحد، أو عبر Telegram بثلاثة أزرار. توافق وأنت في طابور المترو؛ ويتحرك الحوض فور إجابتك. البوابة نفسها والسجل نفسه كما من المكتب.
- **الحوض**: شاهد وكلاءك يعملون؛ كل فقاعة فعل حقيقي من آخر 24 ساعة، والحلقات المنقطة مناصب شاغرة. صفحة علنية قابلة للمشاركة، مع شارة «by zelij.ai».
- **الكتالوج**: ما لا تحتويه النسخة الحرة، مسمًّى بصدق؛ الوحدة المشتراة من الناشر تُثبَّت هنا موقّعة ومتحققًا منها. لا تمر أي عملية دفع عبر المكتب.
- **مصنع البرمجيات**: البنّاء يقرأ ويقترح على مستودع واحد فقط، عبر طلبات دمج تمر من بوابة الأمان (300 سطر، نص فقط، لا أسرار، لا ملفات بنية تحتية، تبعيات بلا ثغرات معروفة وفق OSV)؛ النشر على خادم Linux عبر SSH أو لدى OVH (النطاق وDNS عبر الواجهة البرمجية) مع تبديل ذرّي واختبار دخان ورجوع؛ مسبار النطاق؛ نسخة احتياطية يومية للمكتب. لا يدمج أبدًا، ولا يدفع أبدًا، ولا يلمس المكتب أبدًا.
- **الوكلاء**: مجلد لكل وكيل، ملف `agent.md` بترويسة بسيطة وتعليمات بالفرنسية. أربعة وكلاء: Camille Aubert (رئيسة الديوان)، Élise Tanguy (النمو والتسويق والمنتجات)، Nour Bellamy (المالية والعملاء)، Sacha Ferrand (البنّاء، مصنع البرمجيات). المؤسس يخاطب كل واحد منهم من المكتب؛ والحزمة الموافق عليها التي تعيّن وكيلًا ومهمة تُنفذ فورًا، في حدود الخطة.

## جرّب في دقيقة، بلا مفتاح

```bash
git clone https://github.com/zelij-ai/zelij-core.git && cd zelij-core
docker compose -f docker-compose.demo.yml up --build
```

افتح `http://localhost:8000` وادخل إلى العرض التوضيحي: شركة خيالية، أربعة وكلاء محاكون، قرارات بانتظار الموافقة، حوض يعيد تشغيل يومهم. لا مفتاح، لا حساب، لا تكلفة؛ لا شيء يُرسل إلى نموذج، وكل شيء يختفي عند الإيقاف. عندما تقتنع، انتقل إلى التثبيت الحقيقي أدناه. واجهة المكتب نفسها بالفرنسية.

## البدء

```bash
cp .env.example .env     # مفتاح Claude، السقف، SECRET_KEY، كلمة مرور قاعدة البيانات
docker compose up -d --build
```

يستجيب المكتب على `http://localhost:8000`. بدون SMTP، يُكتب رابط تسجيل الدخول في سجلات الحاوية (`docker compose logs core-app`).

الأدلة الكاملة (بالإنجليزية): **[التثبيت](docs/INSTALLATION.en.md)** (من جهاز فارغ إلى مكتب عبر https، SMTP، مصنع البرمجيات، النسخ الاحتياطي، استكشاف الأخطاء)، **[دليل الاستخدام](docs/MODE-D-EMPLOI.en.md)** (كل صفحة، الوكلاء، القرارات، التكلفة). صور المؤسس والوكلاء توضع في [`portraits/`](portraits/README.md) (الشرح بالفرنسية).

من الصورة المنشورة، دون بناء محلي (`CORE_IMAGE_TAG=v…` في `.env` لتثبيت الإصدار):

```bash
docker compose -f docker-compose.yml -f docker-compose.image.yml up -d
```

محليًا بدون Docker:

```bash
pip install -r requirements-dev.txt
uvicorn core.bureau.app:app --reload
```

## الأمان

ما تضمنه النواة، وما هو مختبر (`tests/test_securite.py`):

- **الوحدات**: لا تُثبَّت الوحدة ولا تُنفذ إلا موقّعة من الناشر (Ed25519)، ويغطي التوقيع بصمة SHA-256 لكل ملف شفرة: أي ملف عُدّل أو أُضيف أو حُذف بعد التوقيع يخرج الوحدة من الخدمة.
- **تسجيل الدخول**: روابط لاستخدام واحد صالحة 20 دقيقة، مخزنة مجزأة في القاعدة؛ كوابح حسب العنوان وحسب IP وعامة على طلبات الروابط، كي لا يصبح المكتب أبدًا مرحّلًا للبريد؛ بدون SMTP مضبوط في الإنتاج لا يُنشأ أي رابط ولا يُسجل.
- **النماذج**: ملف تعريف ارتباط للجلسة بـ HMAC، `HttpOnly`، `SameSite=Strict`، تحقق من المصدر ورمز مضاد لـ CSRF لكل جلسة في كل POST.
- **الصفحات**: سياسة أمان محتوى صارمة (`default-src 'self'`، لا سكربت مضمّن، لا إطارات)، `nosniff`، `X-Frame-Options`، `Referrer-Policy`، وHSTS عندما يكون المصدر https.
- **الوكلاء**: ما يقرأه الوكيل (صفحة ويب، ملف من المستودع) يصله مؤطرًا كمحتوى خارجي، لا كتعليمة أبدًا؛ لا ينفذ الوكيل إلا أدوات بطاقته، وما إن يقرأ بيانًا خاصًا لا يعود قادرًا على نداء غير موقع الشركة؛ لا يقرأ إلا عناوين https علنية (العناوين الخاصة وعناوين الحلقة المحلية والرابط المحلي والأسماء الداخلية مرفوضة عند كل قفزة إعادة توجيه، والاستجابة محدودة الحجم)؛ بوابة الأمان تحجب الأسرار وملفات البنية التحتية وسكربتات الأطراف الثالثة والإطارات ونداءات الشبكة.
- **الحاوية**: مستخدم بلا امتيازات، نظام ملفات للقراءة فقط، بلا صلاحيات (capabilities)، بلا رفع للامتيازات؛ يمكن تثبيت مفتاح مضيف خادم SSH (`SSH_CLE_HOTE`).
- **التصدير المحاسبي**: الخلايا التي تشبه صيغة جدول بيانات تُحيَّد.

للإبلاغ عن ثغرة: `securite@zelij.ai`، دون نشرها قبل الإصلاح. قبل كل إصدار، يجب أن يعود `pip-audit -r requirements.txt` و`bandit -r core scripts -ll` فارغين.

## المساهمة ومتابعة الإصدارات

`CONTRIBUTING.md` (بالفرنسية) يشرح كيف تصل المساهمة إلى إصدار، بما في ذلك القاعدة: هدف نشر مُساهَم به يمنحك الحزمة المقابلة مجانًا مدى الحياة. `SECURITY.md` يشرح كيفية الإبلاغ عن ثغرة. `CHANGELOG.md` يقول ما يغيره كل إصدار وما يبقى على المؤسس فعله.
