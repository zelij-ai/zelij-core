*Акваріум за один змодельований день (тут французькою). У вашій інсталяції кожна картка — справжня дія ваших агентів, наживо і з повтором за двадцять чотири години. Золото — це ви: ніщо зобов'язальне не відбувається до вашого рішення. Обличчя належать вигаданим персонажам.*

## Що робить ядро

- **Офіс**: одна сторінка. Рішення, що чекають, запит до керівника апарату, останні запуски з їхньою вартістю, журнал, агенти, встановлені модулі.
- **Пакет рішення**: мета, пропозиція, чому зараз, варіанти, рекомендація, ризики, оборотність, план, відкат, вплив. Неповний пакет не відкривається. Схвалити, відхилити або попросити змін з обов'язковою вказівкою, яку передають агентові.
- **Правила дому**: ніщо зобов'язальне (гроші, публічність, видалення, необоротне) не робиться без рішення; факт датований і має джерело або позначений «не перевірено»; журнал не стирається.
- **Шлюз**: ключ Claude засновника, вартість кожного виклику, обчислена з використання та датованих публічних тарифів, місячна межа, що блокує.
- **Виконавець**: обмежений цикл викликів (бюджет ходів на агента), скромні інструменти, відмова моделі трактується як результат.
- **Модулі**: єдиний спосіб розширити ядро. Стабільний інтерфейс, маніфест `pack.json`, підписаний видавцем за Ed25519, хеш кожного файлу під підписом, перевірка перед встановленням. Цілі розгортання та додаткові агенти приходять лише цим шляхом.
- **Фінанси**: підтверджені продажі (імпорт Stripe лише для читання або ручне введення з підтвердженням), задекларовані витрати, що повторюються щомісяця, виміряна вартість агентів, журнал місяця, експорт CSV для бухгалтера. Нічого не декларується і не виставляється до оплати.
- **Контакти**: одна картка на людину, обов'язкова правова підстава, строк зберігання, листування, реалізовані права; контакт, що заперечив, більше нічого не отримує, прострочений контакт забувається, лишається тільки журнал прав.
- **Публікація**: сторінка, написана маркетинговим агентом, стає чернеткою, потім рішенням; схвалена, вона пропонується сайту як pull request у GitHub або чернетка WordPress. Останній крок, злиття чи публікація, за вами.
- **У кишені**: кожне рішення приходить на ваш телефон — електронною поштою з двома підписаними одноразовими посиланнями або в Telegram із трьома кнопками. Ви схвалюєте в черзі в метро; акваріум оживає, щойно ви відповіли. Ті самі двері, той самий журнал, що й з робочого столу.
- **Акваріум**: дивіться, як працюють ваші агенти; кожна бульбашка — справжня дія за останні 24 години, пунктирні кільця — вільні посади. Публічна сторінка, якою можна ділитися, зі значком «by zelij.ai».
- **Каталог**: те, чого немає у вільній редакції, названо чесно; модуль, куплений у видавця, встановлюється тут, підписаний і перевірений. Жодна оплата не проходить через офіс.
- **Фабрика ПЗ**: Будівельник читає і пропонує в одному-єдиному репозиторії через pull request'и, що пройшли ворота безпеки (300 рядків, лише текст, без секретів, без інфраструктурних файлів, залежності без відомих вразливостей за OSV); розгортання на Linux-сервер через SSH або в OVH (домен і DNS через API) з атомарним перемиканням, димовим тестом і відкатом; зонд домену; щоденна резервна копія офісу. Він ніколи не зливає, ніколи не платить, ніколи не торкається офісу.
- **Агенти**: одна тека на агента, `agent.md` із простим заголовком і вказівками французькою. Четверо агентів: Camille Aubert (керівниця апарату), Élise Tanguy (зростання, маркетинг і продукти), Nour Bellamy (фінанси та клієнти), Sacha Ferrand (будівельник, фабрика ПЗ). Засновник звертається до кожного з офісу; схвалений пакет, що називає агента і завдання, виконується одразу, в межах плану.

## Спробувати за хвилину, без ключа

```bash
git clone https://github.com/zelij-ai/zelij-core.git && cd zelij-core
docker compose -f docker-compose.demo.yml up --build
```

Відкрийте `http://localhost:8000` і увійдіть у демонстрацію: вигадана компанія, четверо змодельованих агентів, рішення на схвалення, акваріум, що програє їхній день. Ні ключа, ні облікового запису, ні витрат; нічого не надсилається моделі, і все зникає після зупинки. Переконавшись, переходьте до справжньої інсталяції нижче. Сам офіс — французькою.

## Запуск

```bash
cp .env.example .env     # ключ Claude, межа, SECRET_KEY, пароль бази даних
docker compose up -d --build
```

Офіс відповідає на `http://localhost:8000`. Без SMTP посилання для входу записується в журнали контейнера (`docker compose logs core-app`).

Повні посібники (англійською): **[Встановлення](docs/INSTALLATION.en.md)** (від порожньої машини до офісу через https, SMTP, фабрика ПЗ, резервні копії, усунення несправностей), **[Посібник користувача](docs/MODE-D-EMPLOI.en.md)** (кожна сторінка, агенти, рішення, вартість). Фотографії засновника та агентів кладуть у [`portraits/`](portraits/README.md) (опис французькою).

З опублікованого образу, без локального збирання (`CORE_IMAGE_TAG=v…` у `.env` фіксує версію):

```bash
docker compose -f docker-compose.yml -f docker-compose.image.yml up -d
```

Локально без Docker:

```bash
pip install -r requirements-dev.txt
uvicorn core.bureau.app:app --reload
```

## Безпека

Що гарантує ядро і що перевіряється тестами (`tests/test_securite.py`):

- **Модулі**: модуль встановлюється і запускається лише з підписом видавця (Ed25519), і підпис покриває хеш SHA-256 кожного файлу коду: файл, змінений, доданий чи видалений після підписання, виводить модуль з гри.
- **Вхід**: одноразові посилання на 20 хвилин, хешовані в базі; гальма за адресою, за IP і глобальні на запити посилань, щоб офіс ніколи не став поштовим ретранслятором; без налаштованого SMTP у продакшені посилання не створюється і не журналюється.
- **Форми**: HMAC-cookie сесії, `HttpOnly`, `SameSite=Strict`, перевірка origin і анти-CSRF-токен на сесію при кожному POST.
- **Сторінки**: сувора політика безпеки вмісту (`default-src 'self'`, без вбудованих скриптів, без фреймів), `nosniff`, `X-Frame-Options`, `Referrer-Policy`, HSTS при https-origin.
- **Агенти**: усе, що агент читає (вебсторінка, файл репозиторію), приходить до нього обрамленим як зовнішній вміст, ніколи як вказівка; агент виконує лише інструменти зі своєї картки і, прочитавши приватні дані, може звертатися лише до сайту компанії; він читає лише публічні https-адреси (приватні, loopback, link-local адреси та внутрішні імена відхиляються на кожному переході редиректу, відповідь обмежена); ворота безпеки блокують секрети, інфраструктурні файли, сторонні скрипти, фрейми та мережеві виклики.
- **Контейнер**: непривілейований користувач, файлова система лише для читання, без capabilities, без підвищення привілеїв; ключ хоста SSH-сервера можна закріпити (`SSH_CLE_HOTE`).
- **Бухгалтерський експорт**: комірки, схожі на формулу електронної таблиці, нейтралізуються.

Повідомляйте про вразливості на `securite@zelij.ai`, не публікуючи їх до виправлення. Перед кожною версією `pip-audit -r requirements.txt` і `bandit -r core scripts -ll` мають повертати порожній результат.

## Участь і версії

`CONTRIBUTING.md` (французькою) пояснює, як внесок потрапляє у версію, зокрема правило: внесена ціль розгортання дає відповідний пакет безкоштовно назавжди. `SECURITY.md` пояснює, як повідомити про вразливість. `CHANGELOG.md` каже, що змінює кожна версія і що лишається зробити засновникові.

## Тести та контроль публікації

```bash
python -m pytest -q
python scripts/controle_publication.py
```

Контроль публікації відхиляє ключі, IP-адреси, внутрішні коди, особисті адреси електронної пошти, паролі відкритим текстом і терміни з закритого списку (`ZELIJ_CORE_INTERDITS`), який ніколи не входить до репозиторію.
